Things Team will not do.
On purpose, and enforced.

  • Run anything.

    The server has no code path that starts a process, no shell, no file access and no way into anyone’s machine. A test in the codebase fails the build if that ever changes.

    internal/archtest

  • Hold your keys.

    Git, GitHub and agent credentials never reach it. What it stores is coordination: tickets, roles, branch names, commit subjects, pull request state. Never file contents, never diffs.

    metadata only · validated on the way in

  • Let a collision surprise you.

    When two active branches change the same file, both people see it on the board while it is still a conversation and not yet a rebase.

    overlap · behind · conflict · stale

  • Call it done early.

    A ticket cannot reach Done while its pull request is open, and a reviewer cannot sign off their own work. The board means what it says.

    enforced on the server, not in the page

  • Make you rent a network.

    A workspace can have a private network of its own, owned by you, with no account at anyone else’s service.

    Team 2.5 and later

  • Lock out people who don’t code.

    Product managers and designers write tickets, follow progress and sign off outcomes from the browser. No terminal, no repository.
