The app, running in this page.

Start an agent, answer a question, plan the week. The Board, Calendar and Overview share one state, exactly like the real thing.

Drag Backlog cards into Doing. Drag a card from Review into Done to merge it: an agent finishing never merges. Drop unscheduled tasks onto the Calendar and watch them appear on the Board.

One control plane. Your side of the wire.

Each repository is a project with its own board, calendar, Git view and runs. Inside one you see that project and nothing else.

Board

Backlog, Doing, Review, Done. Each run is an interactive session in its own Git worktree: watch it, answer it, send follow-ups. A closed browser never interrupts anything.

Calendar

Schedule the same tasks by day and week, queue by priority, add dependencies. The controller runs the schedule from SQLite while your browser is closed, with explicit missed-time policies.

Needs you

The Control Center is for exceptions: questions, blocked and failed runs, work ready for review, repository risk. Everything else stays quiet.

Git, without force

Fetch, push, merge and open pull requests after checks that refuse rather than guess. Findings say what, why, the evidence and the next step. An agent finishing a run never merges.

Many machines

Pair your own computers with devboard join. Tasks go where the repository and the agent are, by deterministic routing you can read. Usage you cannot measure stays unknown.

Yours

Claude Code or Codex, signed in as you. No hosted backend, no Dev Board account, nothing exposed to the Internet.

Your phone is the remote.

Approve a command from the sofa. Merge a branch from the train. The agents keep working on your computer while you are away from it.

  • Private by construction. Werkbord embeds a Tailscale node, so your phone reaches the controller over your own network. No tunnel, no certificates, no relay of ours.
  • Scan, then Add to Home Screen. devboard open --qr opens the app already signed in.
  • Same state as above. This phone mirrors the demo. Approve something here and the Board follows.

One command.

The installer checks the download against its published checksum before it installs anything, then sets Werkbord up and opens it in your browser.

$curl -fsSL https://raw.githubusercontent.com/micho8cho93/werkbord/main/scripts/install.sh | sh
Needs gitAgents need the claude and/or codex CLI, signed in
devboard statusdevboard opendevboard doctordevboard update
  1. Downloads the release for your computer and verifies its checksum.
  2. Creates your data directory and database, and installs a login service so the controller is always there.
  3. Registers this computer as your first runner.
  4. Joins your private network so a phone can reach it.
  5. Opens Werkbord. Connect GitHub (optional), see which agents it found, pick repositories.

Working with a team?

Werkbord Team is a separate, shared workspace: members, projects, one board, reviews. It coordinates. Every person's own computer still does the work.
