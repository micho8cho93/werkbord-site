Why it’s safe
to hand over.

An assistant that edits your files should be easier to check than to trust. Werkbord is built around that.

Your originals stay put

Every task works on its own copy of the folder. Until you accept a change, the files you know are exactly as you left them.

You see every changed line

Before you accept anything, Werkbord shows what was added, what was removed and in which file. Track Changes, for a whole folder at once.

Nothing is final until you say so

Accepting is called Merge, and it’s a button only you press. An agent that finishes simply waits for you.

When it isn’t sure, it asks

Choose Ask me when needed and the agent stops at real decisions instead of guessing. You answer from your desk or your phone.

There is always a trail

Every accepted change is recorded with what changed and when. That record is what Git, the versioning tool underneath, is for.

The words on the screen,
in plain English.

Project
A folder Werkbord looks after. Programmers call it a repository: a folder that remembers every version of itself.
Task
One instruction, written the way you’d brief a capable assistant.
Agent
The assistant doing the work: Claude Code or Codex, signed in with your own account.
Needs you
A question is waiting. The answer buttons are right on the card.
Blocked
The agent stopped instead of guessing. Pick an answer or reply in your own words.
Review
Finished work, waiting for you to read it.
Merge
Accept the changes into your folder. Only you can press it.
Branch
The draft copy a task works on. It has a name like werkbord/update-prices.
Run
One working session of an agent on a task, kept with its time and, when reported, its cost.
Runner
The computer doing the work. Usually yours; it can be another Mac you own.

Write a task an assistant can finish.

The same rules that make a good brief for a person, a little more literal.

  1. Say what done looks like.

    Improve the about page.

    Rewrite the about page’s first paragraph for someone who has never heard of us. Under 120 words. Keep the last sentence.

  2. Point at the files.

    Fix the typos.

    Fix typos in everything under chapters/. Don’t change any dialogue.

  3. Say what to leave alone.

    Clean up the spreadsheet.

    In orders.csv, standardise the date column to YYYY-MM-DD. Leave every other column untouched.

  4. One outcome per task.

    Update the prices, add a FAQ and redo the footer.

    Three tasks. Each one can be reviewed, and accepted or sent back, on its own.

  5. Ask it to ask.

    Decide which duplicates to keep.

    If two rows could be the same customer, ask me before removing either.

Getting set up,
honestly.

Most of it is clicking. One part happens in Terminal, once. Here is exactly what to expect.

If you have never opened Terminal, ask the most technical person you know for fifteen minutes. After that, everything happens in the Werkbord window and on your phone.

  1. 1

    Download Werkbord and open it

    Drag it to Applications. The first time, it sets itself up in a few seconds. Today it is a test preview, so macOS may ask you to allow it under System Settings → Privacy & Security.

  2. 2

    Install an agent and sign in

    Werkbord drives Claude Code or Codex using your own subscription; it never asks for an API key. Installing one is the step that happens in Terminal. Werkbord checks whether it’s there and links to the maker’s instructions.

  3. 3

    Give it a folder to work in

    Werkbord tracks changes with Git, the same versioning programmers use. The gentlest route: create a repository on GitHub in your browser, connect GitHub in Werkbord (GitHub’s own helper is the other one-time Terminal install), and pick it from the list. Werkbord copies it to your Mac.

  4. 4

    Write your first task

    Pick something small you could check in two minutes. Press Add and start agent, then watch the card move.
